Build a complete, multi-page, production-quality FRONTEND ONLY web app called "CiteCheck AI". Tagline: "Every claim in your content, checked against approved facts before it goes public." Sub-line: "Evidence-first brand governance. Catch brand inconsistencies. Verify claims. Keep humans in control." Context: Codex 48 hackathon, team TECHNOVA (Ugesh Kumar, Team Lead; Riya Sharma, Frontend; Shushma Singh, Presentation and Analyst), Inkloom AI brand-governance brief.

A real backend (FastAPI + Pydantic + SQLite) ALREADY EXISTS. Do NOT build a backend or mock server. Build only the frontend that talks to it.

Stack: Next.js (App Router) + TypeScript + Tailwind CSS + shadcn/ui (Radix) + framer-motion + lucide-react + Recharts.

=====================================================
PART 1 – MANDATORY TECHNICAL REQUIREMENTS (all must be visibly implemented)
=====================================================

A. Responsive & fluid layout architecture
- Mobile-first Tailwind (sm:, md:, lg:, xl:), CSS Grid + Flexbox, rem and clamp()/vw fluid typography, and @container query wrappers on cards and panels so they adapt to their own width.
- Desktop: floating glass "dock" navigation (icon dock, centered at the bottom or left edge, magnifies neighbouring icons on hover like the macOS dock) plus a slim top bar. Mobile: iOS-style bottom tab bar with a "More" sheet. Editor and findings panel are side by side on desktop and a segmented-control tab switcher on mobile. Tables collapse into stacked cards on mobile. Use a bento-grid layout on the dashboard and landing page.

B. State management & server data synchronization
- Zustand for UI/client state (current user/role, dock state, selected finding, editor selection, filters, theme, toasts).
- @tanstack/react-query for ALL server data: useQuery with caching, staleTime and background refetching (refetchOnWindowFocus); useMutation with OPTIMISTIC updates and rollback on error for accept / edit / dismiss decisions, comments, approvals, and fact/guideline/term edits. Skeleton loaders for every loading state, QueryClientProvider at the root.
- All logic lives in custom hooks (useFindings, useDrafts, useVersions, useBrandKit, useGapRadar, useAuditLog, useAuth, useReviewRun), separate from presentational layout components.

B2 (API layer – IMPORTANT). Create /lib/api with a typed fetch client:
- Base URL from process.env.NEXT_PUBLIC_API_BASE_URL. Attach the auth token (Bearer) from the login response, stored in the Zustand store (not localStorage-only secrets in code). On 401 redirect to /login. Parse FastAPI/Pydantic validation errors (422 with a `detail` array) and map them onto React Hook Form field errors. Normalise all errors into one ApiError type shown in toasts and error fallbacks.
- Put ALL routes in a single file /lib/api/endpoints.ts so they can be edited in one place. Assume these REST routes and TypeScript types (Zod-typed responses, parsed at the boundary):
  POST /auth/login → {token, user:{id,name,role}}   (roles: creator | brand_manager | reviewer)
  GET /brand-kit → {guidelines[], facts[], terms[]}
  POST|PATCH|DELETE /guidelines, /facts, /terms   (Fact: id like "FACT-07", text, source, review_date, allow_ai:boolean)
  GET /drafts, POST /drafts, GET /drafts/{id}
  GET /drafts/{id}/versions, POST /drafts/{id}/versions, GET /drafts/{id}/diff?from=&to=
  POST /drafts/{id}/review → runs rules engine + LLM + verifier, returns {findings[], dropped[]}
  GET /drafts/{id}/findings
  POST /findings/{id}/decision → {action: "accept"|"edit"|"dismiss", reason?, edited_fix?}
  GET|POST /drafts/{id}/comments
  POST /drafts/{id}/approve, POST /drafts/{id}/request-changes
  GET /gap-radar, GET /audit-log
  Finding type: {id, draft_id, excerpt, start, end, type, severity, source: "rules"|"ai", source_ref_id, reason, suggested_fix, fix_needs_human:boolean, confidence, status}
  The review response also returns `dropped[]` (candidate findings removed by the verifier) with {candidate, failed_gate (1-5), why}.
- Add an env flag NEXT_PUBLIC_USE_FIXTURES=true that makes the client return small hard-coded fixture data, ONLY so the v0 preview renders when the backend is unreachable. Default is false. Keep fixtures in one folder (/lib/api/fixtures) and clearly comment that they are for preview only.

C. Modular component system & UI kit
- shadcn/ui + Radix + Tailwind. Reusable kit: GlassPanel, GlassButton, Badge (Claim, Unsupported, Unverified, High, Medium, Low, AI-assisted, Rule-based, Needs human review, Outdated fact), SourceChip, SeverityPill, Stepper, DataTable, Dialog, Sheet, Tabs/SegmentedControl, Tooltip, Toast, Skeleton, EmptyState, DiffViewer, FindingCard, HighlightedEditor, GateStepper, Dock.
- Layout components (AppShell, Dock, Topbar, PageHeader) are separate from logic hooks. Fully keyboard accessible, visible focus rings, ARIA labels.

D. Form handling & client-side schema validation
- React Hook Form + Zod with zodResolver on EVERY form: login, add/edit guideline, add/edit approved fact (text, source, review date, allow_ai), add term (banned/preferred), new draft (title + text, non-empty, max length), dismiss-with-reason (required, min 10 chars), edit-fix, reviewer comment, request-changes note. Inline field errors, disabled-while-submitting buttons, success toasts. Schemas live in /lib/schemas.

E. React Error Boundaries & graceful fallbacks
- A reusable <ErrorBoundary> (react-error-boundary) wrapping every major route, the findings panel, Gap Radar chart, DiffViewer, HighlightedEditor, GateStepper and audit table. Friendly glass fallback with the error message and a "Try again" button that resets the boundary and refetches. Add error.tsx, loading.tsx and not-found.tsx. Add a "Simulate error" button under Settings > Developer to demonstrate it. Also show an "API unreachable" fallback state with a retry when the backend cannot be reached.

PART 2 – VISUAL DESIGN (must NOT resemble a cream/red editorial slide deck)
=====================================================

Glassmorphism, "Aurora Night" theme:
- Deep midnight base (#0B1020 to #101735) with slow-drifting blurred aurora blobs in teal (#2DD4BF), violet (#8B5CF6), and warm amber (#FBBF24), plus a very subtle noise texture. A full light mode variant: pale frosted lavender-white (#F4F6FF) with the same accents.
- Every surface is frosted glass: bg-white/[0.06] (dark) or bg-white/60 (light), backdrop-blur-2xl, 1px border white/10–20, layered soft shadows, rounded-3xl, a thin gradient top-edge highlight, and an inner glow.
- Accents: teal = verified / accept / success, violet = AI-assisted, amber = warnings / needs human review / highlights, rose (#FB7185) = unsupported / high severity. Excerpt highlights in the editor look like soft glowing amber underlays (not yellow marker), high severity in rose.
- Typography: Sora or Space Grotesk for headings (bold, tight tracking, NOT italic serif), Inter for body, Geist Mono / JetBrains Mono for small uppercase labels (EXCERPT, SOURCE, GATE 2). Logotype "CiteCheck" with a small animated gradient check-mark glyph and a "AI" capsule, with NO wavy underline.
- Layout personality: bento grids, large rounded tiles, floating dock, a command palette (Cmd/Ctrl+K) for jumping between pages and drafts, soft gradient borders. Landing hero is centered with a live interactive "claim scanner" panel (a glowing scan beam sweeps a sentence, then excerpts light up and a finding card slides up), not a tilted paper card.

iPhone-style smooth hover and motion:
- framer-motion springs (stiffness ~300, damping ~24) and cubic-bezier(0.22, 1, 0.36, 1) everywhere.
- Hover: scale 1.02–1.04, translateY -4px, shadow deepening, glass brightening, plus a cursor-following specular glare on glass tiles and a subtle 3D tilt (max 6deg). Press: scale 0.97 then spring release.
- Dock icons magnify with neighbours; active nav uses a sliding pill (layoutId) like iOS segmented controls; page transitions are soft fade+slide with blur; lists stagger; dialogs and sheets spring up with a blurred backdrop; toasts drop in like iOS notifications; switches have springy knobs; magnetic CTA buttons; animated number counters; animated progress through the 5 gates. Respect prefers-reduced-motion.

PART 3 – APP CONTENT (functionality strictly from the project plan; examples are NEW)
=====================================================

Roles (login with seeded accounts; show demo-account chips on the login page that prefill the form; real auth goes to the backend):
1. Creator – writes drafts, resolves findings, submits versions.
2. Brand Manager – loads/edits the brand kit, controls what the AI may use, sees repeated mistakes (Gap Radar).
3. Reviewer – comments, approves or requests changes, sees version diffs and the audit trail.
Role-based navigation and permissions: only Brand Manager edits Brand Kit and sees Gap Radar actions; only Reviewer approves/requests changes; others are read-only with a tooltip explaining why.

NEW EXAMPLES TO USE EVERYWHERE (landing demo, fixtures, empty-state hints, docs). Use a fictional fintech brand "Lumen Pay" with synthetic data only:
- Example 1 draft "app-store-listing.md": "Lumen Pay is India's most trusted wallet and charges zero fees forever." Findings: "most trusted wallet" → CLAIM, HIGH, AI-ASSISTED, Unsupported, source FACT-07 "Approved claims: no superlatives without proof"; "zero fees forever" → CLAIM, HIGH, source FACT-03 "Pricing: fees reviewed quarterly, no lifetime promises". Suggested fix: "Lumen Pay is a wallet built for simple, everyday payments."
